# ระบบเฝ้าระวังน้ำท่วมเมืองเชียงใหม่ (ต้นแบบ)

เว็บแอปแสดงสถานการณ์น้ำในลุ่มน้ำปิงตอนบนแบบเรียลไทม์ แผนที่ 2D/3D, คาดการณ์ระดับน้ำด้วย AI และจำลองพื้นที่น้ำท่วม

## วิธีรัน
```bash
node serve.js
```
แล้วเปิด http://localhost:5173 (ต้องเปิดผ่านเซิร์ฟเวอร์ เพราะใช้ ES modules) ไม่ต้องติดตั้งแพ็กเกจและไม่ต้องใช้ API key

## Deploy
- เว็บจริง: https://chiangmai-flood-watch.vercel.app (Vercel เชื่อมกับ repo นี้ ทุก push ไป `main` จะ deploy อัตโนมัติ)
- `api/tw.js` เป็น proxy ไปยัง ThaiWater ที่แคช 10 นาที (ข้อมูลย้อนหลังแคช 1 วัน) และกรองเหลือเฉพาะ จ.เชียงใหม่ เพื่อป้องกัน rate limit (429) และลดขนาดข้อมูลจาก ~10 MB เหลือ ~0.4 MB
- บน localhost จะเรียก ThaiWater โดยตรง

## โครงสร้าง
```
index.html        หน้าเว็บ (แผนที่ + แผงข้อมูล 6 แท็บ + แถบเวลา)
css/style.css     สไตล์ (รองรับมือถือ / โหมดมืด)
js/config.js      ค่าตั้งต้น: เกณฑ์เตือนภัย P.1, สถานีอ้างอิง, จุดพื้นที่รับน้ำ
js/api.js         ตัวดึงข้อมูลจากทุกแหล่ง
js/map.js         MapLibre 2D/3D (terrain + อาคาร 3D)
js/flood.js       แบบจำลองพื้นที่น้ำท่วม (HAND + flood-fill)
js/model.js       โมเดล AI คาดการณ์ระดับน้ำ + rating curve + ปรับแก้ GloFAS
js/charts.js      กราฟ (Chart.js)
js/app.js         ควบคุมการทำงานทั้งหมด
```

## โมเดล AI (js/model.js)
- **เป้าหมาย:** ระดับน้ำ P.1 ล่วงหน้า 3, 6, 12 … 72 ชม.
- **วิธี:** Ridge regression แยกโมเดลต่อช่วงเวลาคาดการณ์ (direct multi-horizon) พร้อมช่วงความเชื่อมั่น ~80%
- **ฟีเจอร์:** ระดับ P.1 และแนวโน้ม, ระดับต้นน้ำ P.67 (แม่แตง), ฝนเฉลี่ยลุ่มน้ำย้อนหลัง 6/24/72 ชม., ฝนคาดการณ์ข้างหน้า
- **ข้อมูลฝึก:** ข้อมูลรายชั่วโมงจริง ฤดูฝน 2567–2568 (รวมน้ำท่วมใหญ่ ต.ค. 2567 ที่สูงสุด 5.30 ม.) ฝึกในเบราว์เซอร์และเก็บแคชไว้ 30 วัน
- **ผลทดสอบ** (ฝึกด้วยปี 2567 ทดสอบกับปี 2568): RMSE ที่ 24 ชม. = 0.23 ม. เทียบกับ 0.29 ม. ถ้าเดาว่าระดับคงที่ และ 72 ชม. = 0.41 ม. เทียบกับ 0.52 ม.
- **ระยะยาว 30 วัน:** GloFAS ปรับค่าเอนเอียงด้วยอัตราการไหลจริงที่ P.1 แล้วแปลงเป็นระดับน้ำผ่าน rating curve ที่สร้างจากข้อมูลจริง

## แบบจำลองน้ำท่วม (js/flood.js)
1. ลากแนวแม่น้ำปิงตามท้องหุบเขาใน DEM (Dijkstra ผ่านสถานีวัดน้ำ)
2. HAND = ความสูงเหนือระดับริมตลิ่งของจุดลำน้ำที่ใกล้ที่สุด
3. ระดับน้ำเหนือตลิ่ง = ระดับน้ำ − ระดับตลิ่งที่สำรวจจริงของแต่ละสถานี
4. ท่วมเมื่อ HAND < ระดับเหนือตลิ่ง และพื้นที่ต้องเชื่อมต่อกับลำน้ำ

**ข้อจำกัดสำคัญ:** SRTM เป็นแบบจำลองพื้นผิวที่รวมอาคารและต้นไม้ ทำให้เขตเมืองชั้นในสูงเกินจริงราว 3–5 ม. แม้จะกรองด้วย morphological opening แล้ว แบบจำลองจึง **ประเมินน้ำท่วมในเมืองชั้นในต่ำกว่าจริง** (เช่น ย่านไนท์บาซาร์และวัดเกตที่ท่วมจริงในปี 2567) และอาจประเมินพื้นที่โล่งสูงเกินจริง

## แนวทางพัฒนาต่อ (เรียงตามผลกระทบ)
1. **DEM ที่ดีขึ้น:** เปลี่ยน `CONFIG.terrainTiles` เป็นไทล์ Terrarium ที่สร้างจาก LiDAR ของกรมโยธาธิการฯ/GISTDA หรือ FABDEM (DEM ที่ตัดอาคารออกแล้ว) และใส่แนวคันกั้นน้ำริมปิง
2. **สอบเทียบกับเหตุการณ์จริง:** เทียบพื้นที่ท่วมจากภาพดาวเทียม GISTDA (ต.ค. 2567) เพื่อปรับพารามิเตอร์
3. **โมเดล AI ขั้นสูง:** LSTM/Transformer ฝึกฝั่งเซิร์ฟเวอร์ด้วยข้อมูลหลายปี (2554–ปัจจุบัน) เพิ่มสถานี P.75, P.4A, P.20, P.21 และอัตราระบายเขื่อนแม่งัด/แม่กวง
4. **Backend + cron:** ดึงข้อมูลทุก 10–15 นาที เก็บประวัติลง DB และส่ง push/LINE แจ้งเตือนเมื่อคาดว่าเกิน 3.70 ม.
5. **แบบจำลองชลศาสตร์** (HEC-RAS 2D / LISFLOOD-FP) รันล่วงหน้าหลายระดับน้ำ แล้วให้เว็บเลือกแผนที่ที่ใกล้ที่สุด จะแม่นกว่าวิธี HAND

> ใช้เพื่อการเฝ้าระวังเบื้องต้นเท่านั้น ให้ยึดประกาศของ สชป.1, ปภ. และจังหวัดเชียงใหม่เป็นหลัก
> เกณฑ์ 3.20 / 3.70 / 4.20 ม. ใน `config.js` ควรตรวจสอบกับเกณฑ์ทางการอีกครั้ง
